## Дополнительно (итерация после проверки)
- API админки теперь принимает `admin_token` не только из `Authorization`, но и из cookie. Это снижает риск пустых данных после обновления страницы/сессии.
- `Товары` в админке теперь запрашиваются с admin-token; административный запрос больше не подменяется статическим fallback при ошибке базы.
- `Отзывы` открываются по умолчанию в режиме `Все`, а API больше не возвращает успешный пустой список при таймауте БД.
- Входящие письма через webhook больше не падают с 500 при отсутствии `RESEND_WEBHOOK_SECRET` в env: секрет берётся из настроек БД, а если его нет, письмо всё равно сохраняется из payload.
- В webhook писем добавлена обработка `to` как объекта, а не только строки/массива.
- Медиатека при чтении синхронизирует БД с файлами и добавляет найденные на диске фото в выдачу даже если запись в БД не успела сохраниться.
- Открытие чека исправлено повторно: вкладка создаётся без `noopener`, чтобы браузер не возвращал `null` и не блокировал загрузку HTML.
- Старые разделы `Информация / Аккаунт / Техническое / SEO / Контент / Страницы` удалены как отдельные admin routes, а не только скрыты/редиректнуты.
- Быстрая ссылка `Контент` удалена с дашборда; иконка отзывов на дашборде заменена на звезду.
- Из админских чтений `counts`, `dashboard`, `reviews` убраны `Promise.race`-таймауты, которые могли оставлять фоновые Prisma-запросы висеть и забивать пул подключений.
- `GET /api/orders` переписан без тяжёлого вложенного `items.product`: заказы, позиции и товары читаются отдельными быстрыми запросами и собираются в прежний формат ответа.
- `GET /api/admin/email` переведён на последовательное чтение списка и счётчика непрочитанных, чтобы не создавать лишнюю параллельную нагрузку на пул БД.
- Удаление писем заменено на архивирование (`status: archived`) без физического удаления записи из базы.
- В общий Prisma retry-слой добавлен таймаут операции с пересозданием Prisma client, чтобы long-running PM2-процесс не зависал навсегда на подвисшем соединении БД.
- Для критичных admin GET (`orders`, `email`, `reviews`, `counts`) чтение переведено на fresh Prisma client per request с закрытием соединения после ответа, чтобы обходить подвисший singleton в long-running PM2.
- Для fresh Prisma client добавлен собственный таймаут операции с гарантированным `$disconnect()` в `finally`, чтобы даже зависший запрос не держал HTTP до nginx timeout.
